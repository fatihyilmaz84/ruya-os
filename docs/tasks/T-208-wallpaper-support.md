# T-208 — Wallpapers: choose the picture behind the shell

Status: in-progress · Phase: 2 · Depends: — · Area: shell, services · Size: M · Owner: builder

## Goal
The owner can pick a wallpaper in Settings. It is the picture behind Home when there is no hero art and, blurred, behind pages and glass (`04` §3.5 layer L0, §3.6). Owner request, 2026-11-06. Today L0 is the hero art or the tinted blobs.

## Read first
- `docs/specs/04-design-system.md` §3.5 (L0 backdrop: "hero art (Home), blurred hero art (pages), tinted blobs when there is no art"), §3.6 (one shared blurred copy, never a second full-screen blur), §1 principles 3 and 5, §3.8 (grain, shadows), §7 accessibility (legibility)
- The backdrop component(s) (`Backdrop*.qml`, the tint/blob code), `DeviceSettings`, `DisplayPane.qml`/Settings panes pattern (`shell/PATTERNS.md`), Storage/Library backends (reading images from USB volumes), `Theme.qml` tints
- The quality tiers (`effectsQuality`): blur levels per tier

## Scope
1. **Sources:** (a) a small bundled set (4 to 6 wallpapers in the Dreamglass look: abstract gradients and soft shapes **made for this project**, licence-clean, 1920x1080, compressed, plus a "Default (animated blobs)" entry that is today's look); (b) pictures from a mounted USB drive (jpg, png, webp; one folder level `Wallpapers/` or `Pictures/`, never executing anything, size-limited, listed by name with a thumbnail); (c) the Store/Games art is not a wallpaper source here.
2. **Setting + storage:** `DeviceSettings.wallpaper` (id or a copied file). A USB pick is **copied** (downscaled to the screen size, max 3840x2160, re-encoded jpg/webp) into the shell's own state directory so removing the stick does not lose it; the copy is done off the GUI thread with a progress/failed state; a size cap and a count cap (say 12 user wallpapers) with a Delete row. Per-profile wallpapers are a later step (profile homes are 0700 and unreadable by the shell: Inbox).
3. **Rendering:** decode asynchronously (`Image { asynchronous: true; sourceSize }` at the screen size), cross-fade on change over `tintMs`; Home shows the wallpaper under a legibility scrim (`heroScrim` rules apply) when there is no hero art and keeps art-led heroes when there is; pages show it through the **one shared blur** (no second full-screen blur); the Performance tier shows the unblurred, darkened wallpaper; a missing or corrupt file falls back to the default look with a log line and a toast "Wallpaper could not be loaded".
4. **Settings UI:** Settings -> Display & motion (or a new "Appearance" pane, decide per `02`/`04`): a Wallpaper row opening a picker grid of thumbnails (controller-first, focus ring, the current one marked), "Add from USB drive..." when a drive with images is mounted, Delete for user wallpapers, "Dim wallpaper" slider (0 to 60 %). `qsTr`, Turkish.
5. **Memory/perf budget:** one decoded wallpaper in memory (plus the one being faded in); thumbnails 320 px; measure shell RSS and frame time on the Dell with a 4K source (Outcome numbers).

## Out of scope
- Video or animated wallpapers, per-profile wallpapers, wallpaper from the web or the Store, automatic colour matching (Inbox: an accent from the wallpaper; compare the study's extraction in `04` §3.8 first), screen savers (T-202).

## Outcome

**Built.**
- **Library** (`src/wallpaper/Wallpapers.{h,cpp}`, a `QML_ELEMENT QML_SINGLETON`, in `CMakeLists.txt`): `bundled` (from `assets/wallpapers/catalog.json`), `user` (the copies, with `index.json` for name and brightness, in `Wallpapers.directory`: `~/.local/share/ruya-shell/wallpapers`, `RUYA_WALLPAPER_DIR`, or a temporary folder while settings are ephemeral), `usbImages` (`scanUsb(mountPoints)`: jpg/png/webp directly inside a folder `Wallpapers` or `Pictures` of each mount, regular files only, at most 25 MB and 40 megapixels, at most 60 listed, off the GUI thread; a newer scan drops an older result), `importFile(path)` (worker thread through `QThreadPool`: probe, `QImageReader` with a scaled size, scale to cover the screen but never enlarge and never beyond 3840x2160, flatten onto `Theme.background`, JPEG 88, brightness `peak`; the file name is the hash of the result, so a picture twice is one copy; `copyState` "copying"/"idle" and `copyFinished(status, id, name)` with `ok`, `limit`, `unsupported`, `too-large`, `unreadable`, `io`), `remove(id)`, `requiredDim(peak)`. At most 12 copies. Nothing on a drive is run; symlinks are skipped; a stray file in the directory that the index does not list is removed at start. The mock helpers for tests (`mockPrepareUsb`, `mockPlantCorrupt`, `mockFillUser`, `mockSetCopyDelay`, `mockReset`) do nothing outside the mock mode.
- **Settings** (`DeviceSettings`): `wallpaper` ("" is the default look, else a bundled id or `user:<file>`; `isValidWallpaper` rejects a path or `..`) and `wallpaperDim` (0 to 0.6, default 0.2), both persisted.
- **Rendering** (`WallpaperLayer.qml`, new; `Shell.qml`, `Backdrop.qml`, `AppArt.qml`): see `04` §3.5 "Wallpaper". Two async `Image`s cross-fade over `tintMs`; the old one stays below until the new one covers and is then released; the blobs rest (`Backdrop.shown`) while covered; one `MultiEffect` over a quarter-size `ShaderEffectSource` blurs on pages (the shared copy, no second full-screen blur; High 64, Balanced 32); Performance has no blur item and a dim of at least `Theme.wallpaperDimUnblurred` (35 %, the only new token); the hero `ArtLayer` is `bare` (clear fill) over a wallpaper, so an item without art shows the wallpaper under the unchanged scrims. A failed load or a missing id: a log line, the toast "Wallpaper could not be loaded", and the setting goes back to the default look.
- **Legibility rule** (my addition: blur cannot make a bright picture legible): each picture has a `peak` brightness and `Wallpapers.requiredDim` raises the dim until white text keeps 4.5:1 over it. Numbers (relative luminance of `text` 0.904): Dusk peak 0.036, Aurora 0.044, Orchid 0.052, Ember 0.067, Lagoon 0.090 need no extra dim and give 13.3, 12.4, 11.6, 10.5, 9.1 : 1 at the default 20 %. Daybreak (the bright one, peak 0.822): 1.09:1 raw, 4.52:1 with the 52 % dim it gets. Pure white: 56 % dim, 4.52:1. So the "Dim wallpaper" slider is a minimum for a bright picture (the row still reads 20 % while Daybreak is dimmed 52 %). On Home the left hero scrim (75 % of `#05070d`) lies on top as before, so the hero text sits on a darker area than these numbers say; the top-bar pills (`glassStrong`, 12 % white) over a bright area keep the pre-existing 0.9:1 caveat of `04` §3.6, now helped by the dim (not measured).
- **Settings UI** (`DisplayPane.qml`, `WallpaperPicker.qml`; `SettingsPage.qml` passes `overlay`): a "Wallpaper" row in Display & motion (not a new category: the category list already scrolls at nine, `02` §1.2) that opens the picker modal, and a "Dim wallpaper" slider (hidden with the default look). The picker: 4-column grid of 320 px thumbnails, the current one badged, "Add from USB drive..." while a mounted removable volume has pictures, "Delete" for the highlighted copy, the drive's pictures in the same grid with "Copying..." while the worker runs. Controller keys only; it accepts every key; focus returns to the row. English and Turkish strings (25), `.ts` files refreshed.

There is no top-level licences folder in this repo; the fonts keep theirs in `shell/fonts/`, so the wallpapers' is in `shell/assets/wallpapers/`.

**Deviations and decisions.** The pane is Display & motion, not a new "Appearance" category (above). The copy is always re-encoded as JPEG (the task allowed jpg or webp; webp needs a plugin the image lacks). The setting goes back to the default look when a picture cannot be loaded (the task: "falls back to the default look"). The dim slider is a minimum (legibility rule). One token added: `Theme.wallpaperDimUnblurred`. `AppArt` got `bare`. No D-Bus or service change: the shell reads the mounted volume itself, as the task scoped it.
