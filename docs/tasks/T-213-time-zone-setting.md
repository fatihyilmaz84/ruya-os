# T-213 — Time zone: choose it in setup and in Settings, so local time is right

Status: in-progress · Phase: 2 · Depends: — · Area: api, services, shell · Size: S · Owner: builder

## Goal
The console knows the owner's time zone. Today the clock shows UTC (first noticed in the 0.0.40 try-out, still true on the Dell). Local time is needed by the clock in the shell, the update restart window ("03:00 to 05:00 local", `ruya-update`), bedtimes and daily limits (T-211) and the screen saver/sleep timelines (T-202).

## Read first
- `docs/specs/01-platform.md` ("Schedule" paragraph: the restart window and its use of local time), `docs/specs/02-shell.md` §1.3 (first-boot setup, T-106) and the System pane, `ruya-update`'s schedule code and tests (how it gets the local hour), the clock in the status cluster (`ProfileStatus.qml`/`StatusCluster`), `ruya-devices` structure for a new small interface or `ruya-profiles` if more fitting
- systemd: `timedatectl` (`list-timezones`, `set-timezone`), `org.freedesktop.timedate1` on the system bus (`SetTimezone`, `ListTimezones`, `Timezone` property), `chronyd` (NTP is on); polkit action `org.freedesktop.timedate1.set-timezone`

## Scope
1. **Contract first:** a small `org.ruyaos.Devices1.Time` interface (or the pane talking to `timedate1` through a thin service call): `GetTimezone() -> s`, `ListTimezones() -> as` (IANA names, grouped by region in the UI), `SetTimezone(name) -> status` (admin only: the caller's active profile is an admin, as for the other admin calls; unknown names `invalid`), `TimezoneChanged` signal, plus `NtpSynchronised` property for the "clock not set yet" case. The service (`ruya-devices` user unit cannot call `timedate1` without polkit: add the narrow polkit rule for exactly `org.freedesktop.timedate1.set-timezone` and only for the user `ruya-shell`, like the power rules, or run the call from a root service: pick the smaller and say why).
2. **Shell:** first-boot setup gets a "Where are you?" step (region -> city list, controller-first, a sensible default from the language, skippable; the choice needs no admin because setup runs before profiles exist), Settings -> System gets a "Time zone" row for admins; the clock uses the zone at once (and 12/24 h follows the language as now); the update restart window and any other "local time" consumer read the zone (check `ruya-update` uses `localtime`, not UTC; add a test with a fake zone).
3. **Mock and tests;** a zone change moves the clock and the update schedule's local hour in tests.

## Out of scope
- Automatic detection by IP or GPS, DST rules beyond what tzdata gives, a 12/24 hour override, the system locale (language is separate).

## Outcome
Verified: host (vm pending: `scripts/vm-devices-check.sh time`)

**What was built.** The console now has a time zone it can be asked for and told.
- **Contract** `org.ruyaos.Devices1.Time` in `api/dbus/org.ruyaos.Devices1.xml`: `GetTimezone`, `ListTimezones`, `SetTimezone(name) -> ok | invalid | forbidden | failed`, property `NtpSynchronised`, signal `TimezoneChanged`. `forbidden` (not `refused`, which Devices1 uses for the pairing window's uid rule) because it is the admin rule `Update1`/`Store1` already call `forbidden`.
- **Service** (`ruya-devices`): `time.rs` (pure core: caller rule, name validation, change detection, fake timedated) and `timedate.rs` (the `org.freedesktop.timedate1` client, Linux only), `TimeIface` and `watch_time` in `dbus.rs`. **Smaller of the two options: no new service, one polkit rule** (`image/rootfs/usr/share/polkit-1/rules.d/50-ruyaos-time.rules`: exactly `org.freedesktop.timedate1.set-timezone`, only for `ruya-shell`; `ruya-devices` already runs as that user, so no unit, bus policy or hardening change). Caller rule: root, or the shell while Profiles1's active profile is an admin **or no profile exists** (setup needs no admin); fails closed. `forbidden` is answered before the name is looked at.
- **`ruya-update` fix (found while checking "uses local time, not UTC"):** it did use `localtime_r`, but glibc's `localtime_r` reads the zone once and never again, so a zone chosen while the service runs would not have counted until the next start. `SystemClock` now calls `tzset()` first (declared by hand, the `libc` crate does not have it); the arithmetic is the new pure `local_minute_of_day(now, offset)`; `ZonedClock` is the test clock in a zone.
- **Shell:** `TimeZone` singleton (`shell/src/time/`: backend, mock, D-Bus client; named `TimeZone` because `Time.h` would shadow `<time.h>` on Windows), `ZoneChooser.qml` (region list + city list), `ZonePicker.qml` (the Settings modal), setup step 2 "Where are you?" (steps are now 6; Start skips; B goes back), the admin-only "Time zone" row in Settings -> System with a toast for the result, a note when the clock is not NTP-synchronised, and the status-cluster clock now reads `TimeZone.clockText` (computed from the zone name with `QTimeZone`, so a change shows at once). Turkish and English strings added.

**Tests.** Rust: 15 in `time::tests` (caller rule, plausible names, list, statuses and ordering, same-zone no-op, refusal by timedated, outside change, NTP change), 4 in `schedule::tests` (`local_minute_of_day`, window 03:00-05:00 local not UTC, `ZonedClock`, and Linux-only `the_system_clock_follows_a_zone_change_while_running`), 2 in `service::tests` (restart announced at 03:40 Tokyo and not in UTC, and not at 03:10 UTC in Tokyo; a zone change moves the window at once and calls the announced restart off). QML: new `tst_timezone.qml` (mock statuses, grouping, late-reply guard, clock text per zone, the status clock follows a change, System row admin-only, picker region -> city with focus asserted, Back, refusal toast, NTP note); `tst_setup.qml` has six new tests (region -> city -> done with controller keys only and focus asserted, language default, Back order, Start skip, choice kept when going back, a refusal does not block) and the existing ones moved to six steps; `tst_i18n.qml` and `tst_accessibility.qml` follow the new step. **Revert checks:** removed `tzset()` -> the Linux zone-change test fails (run in WSL, `TZ=HST10: 1171, want about 31`); the clock binding back to `new Date()` -> `test_the_status_clock_follows_a_zone_change_at_once` fails; `visible: pane.isAdmin` off the row -> `test_the_row_is_for_admins_only` fails; `NobodyActive => true` in `caller_may_set` -> `the_shell_may_not_set_for_anyone_else` fails.

**Checks.** `dev.ps1 test` ALL GREEN (605 QML passed, 53 skipped; 504 Rust). `dev.ps1 shots`: my screenshots (`14-setup-timezone-region`, `15-setup-timezone-city`, `16-settings-timezone-row`, `17-settings-timezone-picker`, plus `11`-`13` setup) were reviewed; 8 other shots tests fail (BatteryCluster, Glass, Glide x2, GlideSettings, Lockout, Settings scroll cue, Wallpaper), all waiting on animations, in files this task does not touch; **the same two I tried (`Wallpaper`, `Lockout`) fail the same way with main's own build**, so the desktop/GPU session is the cause, not this change. The picker and row shots set reduced motion so they show the final state whatever the render speed.

**Deviations / decisions.** (1) The wizard goes on without waiting for the `SetTimezone` answer and does not report a refusal (the contract allows setup, so a refusal means something is wrong; Settings can set it); an Inbox line below. (2) "12/24 h follows the language as now": the clock was always 24 hour ("HH:mm") and stays so; no override was added (out of scope). (3) A zone for the language default is only London or Istanbul; other languages do not exist yet. (4) City names are IANA's, not translated.
