# T-225 — Crash reporting: capture, symbolise and (with consent) send

Status: todo · Phase: 3 · Depends: T-224 · Area: services, image, scripts, shell · Size: M · Owner: lead

## Goal
When the shell or a console service crashes, the project can see what happened without asking the user to do anything, and the user stays in control. Owner request, 2026-11-06: "which crashes occur and report them; the user can turn them all off". Proof that it is needed: on the first real-hardware run the shell segfaulted when a Bluetooth headset disconnected (T-197); the only evidence was a core dump found by SSH.

## Read first
- T-224 (service, consent, settings, schema, queue, send), `docs/specs/01-platform.md` (services, hardening), `systemd-coredump` (`coredumpctl`, `/var/lib/systemd/coredump`, the `Storage=`/`ProcessSizeMax=` settings, the `.coredump` metadata in the journal: `COREDUMP_EXE`, `COREDUMP_SIGNAL`, `COREDUMP_PID`, the stack trace in `coredumpctl info`), `ruya-session` (`AppExited` reasons: `crashed`, `killed`, `launch-failed`), `image/Containerfile` and `scripts/build.sh` (how binaries are built and stripped), the `Restart=always` of `ruya-compositor@.service`
- Evidence format from the Dell (T-197): `coredumpctl info` lists threads with frames like `on_remote_data (libpipewire-module-protocol-native.so + 0x91f7)` and, for our binary, `main (ruya-shell + 0xcc29)`; build ids are available per module.

## Scope
1. **What counts as a crash report (closed set):** (a) a **core dump of a RuyaOS process** (`ruya-shell`, `ruya-*` services, `ruya-compositor`): signal, executable name and version, thread stacks as **module + function + offset** frames (and the module build-ids for symbolication), the shell's last 20 log lines **after scrubbing**, the RuyaOS version, the hardware class summary (GPU vendor/driver) from T-224's report; (b) a **service failure** (a `ruya-*` unit entering `failed` or restarting more than N times in a minute: unit name, result, exit status, restarts); (c) a **third-party app crash**: only app id, app version, exit reason (`crashed` with exit code or signal), runtime version; **never** a stack, memory, logs or paths of someone else's app.
2. **Never included:** memory contents, environment variables, command lines with arguments, the profile or user names (frames from a profile's home are reduced to the module name), file paths under `/var/home`, IP or MAC addresses, Wi-Fi names, anything the user typed. A **scrubber** (pure, tested) removes or rewrites such strings from every text field before it is queued, and a report that still matches a PII pattern is dropped, not sent.
3. **Capture:** a small collector in `ruya-telemetry` (or a helper it runs) subscribes to the journal for `systemd-coredump` entries and unit failures (`sd_journal`/`journalctl --follow -o json`, filtered, not polling), reads only the stack text `coredumpctl info` produces (never copies the dump into a report), builds the closed schema, and queues it only when the user has answered **Share** to crash reports (T-224). With "Don't share" nothing is collected; the local core dump stays where systemd keeps it (size-capped, `systemd-coredump` defaults, documented) for the owner's own debugging over SSH.
4. **Symbols (the part that makes reports useful):** the build keeps **debug symbols per release**: `scripts/build.sh` and the Containerfile stages produce split debug info for `ruya-shell` and the Rust services (Rust `split-debuginfo`/`strip = "debuginfo"` into a `.debug` artifact, C++ `-g` into `objcopy --only-keep-debug`), named by build-id, archived next to each image (`output/symbols/<version>/<build-id>.debug`, kept out of the image so it does not grow); `scripts/symbolicate.py` turns a report (module + build-id + offset) into function names and file:line using `addr2line`/`eu-addr2line`/`llvm-symbolizer` from the archive, for the owner's side; a worked example in `docs/dev-setup.md` using a real core from the VM (a test crasher). The server never needs the image.
5. **Shell:** Settings -> Privacy lists "Crash reports" with the switch from T-224; a small **"The console restarted after a problem"** toast after a crash recovery when sharing is on, never a modal; **View what is shared** shows each pending crash as a readable text before it is sent; when sharing is off nothing is shown or collected. Turkish.
6. **Test crasher:** a debug-only way to cause a crash in a controlled place (`ruya-shell --debug-crash` guarded so release behaviour is unchanged and apps cannot trigger it; a test Flatpak app that segfaults for the third-party path) for the VM check.

## Out of scope
- Uploading core dumps, minidump formats, an in-console issue tracker, crash-loop auto-rollback (greenboot exists), UI for choosing individual reports to send, the production backend.

## Acceptance criteria
- [ ] Rust tests: the closed crash schema (a test fails on an extra key); the scrubber on realistic samples (paths under `/var/home/ruya-p3/`, a profile name in a log line, MAC/IP/SSID, an email, a Bluetooth address) leaves none of them; a dropped report when something still matches; a frame from a home path becomes module-only; third-party crash reports carry nothing beyond the three fields; deduplication (the same crash 50 times queues a count, not 50 reports); size caps; no capture without consent (fake consent source); parsing real `coredumpctl info` samples from the Dell (T-197's dump as a fixture, trimmed).
- [ ] The build produces split debug info for the shell and the services with build ids matching the shipped binaries (a script check compares `readelf -n` build ids of the image binaries with the archive) and `symbolicate.py` resolves a frame of a test crash to the expected function (a test with a small fixture binary).
- [ ] VM (lead run): `vm-crash-check.sh`: with sharing off a debug crash produces no report and no queue; with sharing on exactly one report arrives at the reference receiver, scrubbed, with module/offset frames and build ids, and `symbolicate.py` names the crashing function from the archived symbols; a crashing test app yields only the three fields; the shell restarts (T-201 will cover the user-visible recovery); the receiver rejects a report containing a path under `/var/home`.
- [ ] `.\scripts\dev.ps1 test` and `shots` ALL GREEN; `systemd-analyze security` of the touched units not worse.
