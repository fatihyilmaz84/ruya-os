# T-227 — UI sounds and ambient atmosphere: sound themes, one bundled theme, a guide for makers

Status: in-progress · Phase: 2 · Depends: — · Area: shell, image, docs · Size: M · Owner: builder

## Goal
The shell sounds like a console (owner request, 2026-11-06: "ambient sounds, existing or generated, I like how PlayStation does it"): a complete set of short UI cues, and a quiet ambient atmosphere behind Home and the menus that fades away when an app is in front. Everything comes from a **sound theme**, a folder with a manifest, so that anyone can make another one. RuyaOS ships **one** theme; the developer guide explains how to build others.

Today only three cues exist (`shell/sounds/{navigate,select,back}.wav`, played by `Sfx.qml`) and the Ambient channel (`02` §5, slider in Settings -> Audio) plays nothing.

## Scope
1. **Sound theme format** (document it in `docs/developers/sound-themes.md` and `02` §5): a folder `<id>/` with `theme.json` (`name`, `author`, `licence` as an SPDX id, `version`, `cues` mapping cue names to files, optional `ambient` with `file`, `loop` start/end in ms and a `gain`), the audio files (WAV for cues, Ogg Vorbis or Opus for the ambient loop), and a `README`. Rules: cues <= 1.5 s and <= 200 KB each, mono or stereo 48 kHz, peak below -3 dBFS, ambient <= 3 MB; unknown cues fall back to the bundled theme, a missing cue is silent, a broken theme is ignored with a log line (never a crash, never a blocked boot).
2. **Cue set** (names are the contract): `navigate`, `select`, `back`, `error` (wrong PIN, refused), `notification` (toast), `warning` (sticky toast), `open` and `close` (overlay/Guide), `page` (page change), `volume` (the OSD tick), `startup` (once at the shell's first frame), `toggle-on`, `toggle-off`. `Sfx.qml` exposes one function per cue plus a counter (tests rely on them); wire the cues into the existing components in place of ad-hoc calls, only where the meaning is clear. The UI sounds channel scales all of them; reduced motion does not silence sound, "UI sounds" 0 does.
3. **Ambient:** a seamless loop on the Ambient channel (`QMediaPlayer` or `QAudioSink`: check which plays Ogg on both Windows and Fedora's Qt build; QSoundEffect is WAV only). Plays on Home and the menus, fades out over 800 ms when an app is in the foreground or the screen saver/sleep starts, fades in on return, ducks about 8 dB under cues. Default: **on at the Ambient slider's default level** (recommendation, to be confirmed by the owner after hearing it; it is one setting default); Settings -> Audio gets an "Ambient sound" toggle next to its slider, and a "Sound theme" choice row.
4. **Themes on disk:** bundled theme under `/usr/share/ruyaos/sounds/<id>/` (Qt resources in the Windows dev build). The "Sound theme" row lists the bundled one and any folder found in `RuyaOS/sounds/<id>/` on a mounted USB drive, validated by a pure-function checker (the same one used by the lint, below); choosing a drive theme copies it to the shell's own data directory so it keeps working when the drive is removed. Nothing is ever executed or auto-loaded from removable media (security invariant): files are parsed as data only, size limits enforced before decoding.
5. **The bundled theme "Dreamglass"**: generated by a script in the repo (`scripts/make-sounds.py`, numpy, deterministic, no samples from anywhere else), so the audio is our own work and **CC0**; state that in the theme's `theme.json`, the README and `docs/image-packages.md`/licence notes. Character: soft glassy sine/bell partials with short attack and a rounded tail, low and unobtrusive, matching the frosted-glass look; the ambient is a slow evolving pad (two or three detuned sine layers with a gentle filter drift), a loop of about 60-90 s with no click at the seam. Keep the generator parameters readable so a maker can start from it, and say in the guide how to run it.
6. **Checker and lint:** a function that validates a theme folder (manifest schema, limits, cue names, loop points inside the file, decodable) used by the shell and by `scripts/lint-sound-themes.ps1`, which runs the bundled theme and the guide's example through it from `dev.ps1 test` (and a fixture folder with broken themes that must be rejected).
7. **Developer guide:** `docs/developers/sound-themes.md` (format, cue list with when each plays, loudness and length limits, how to try a theme with a USB stick on a console or in the dev build, the licence expectations, an example theme folder under `samples/sound-theme-example/` with the generator's output replaced by a tiny set), linked from the README, with the Sources footer.
8. **Turkish** strings for the new rows.

## Out of scope
- Music players or game audio, per-profile themes (later, needs profile preferences), a theme store, voice or speech, spatial audio, haptics.
- Changing the PipeWire stream roles or WirePlumber ducking policy beyond what the Ambient channel already specifies (note a needed change as an Inbox line).

## Acceptance criteria
- [ ] Checker tests: a valid theme passes; each limit and each schema error is rejected (oversize file, cue too long, loop outside the file, unknown extension, missing manifest, path escaping the folder `../`); a missing cue falls back; the bundled theme and the example theme pass.
- [ ] `Sfx` tests: every cue function plays through the theme and bumps its counter; the UI sounds channel scales it; gain 0 is silent; a broken theme leaves the bundled one active.
- [ ] Ambient tests (properties, not sound): plays on Home, stops (fade finished) when an app is foreground or the saver starts, returns after; the toggle and level take effect; ducking is requested under a cue.
- [ ] The Settings -> Audio rows (toggle, theme choice) work with a controller and keep focus when the drive list changes (screenshots English and Turkish read against `04` §8).
- [ ] The generator is deterministic (two runs, identical bytes) and the output meets the limits; the loop seam is checked by a test (first and last samples of the loop continue smoothly).
- [ ] `lint-dev-docs.ps1` passes for the new chapter; `.\scripts\dev.ps1 test` and `shots` ALL GREEN.
- [ ] Listening (lead run, the Dell or the VM with `-Audio`): the owner hears the set and the ambient loop; adjust the generator parameters on their feedback (Inbox line if they want a different character).

## Outcome
Verified: host (vm pending: scripts/vm-sounds-check.sh; the listening criterion is the owner's, on the Dell or a VM with -Audio)

UX notes: states reached: Settings -> Audio with the new **Ambient sound** switch under the Ambient slider (on by default), the **Sound theme** choice row at the end (Left/Right through the bundled theme and the copies; with one theme it stays put and keeps focus), and one row "Use “Name” from the USB drive" for every valid theme on a mounted stick (value "Copying…" while the worker copies; toast "Sound theme: Name" on success, a warning toast when the checker or the limit refuses). Back leaves the pane to the category list as in every pane; the pane still opens on the first output. Focus: the rows follow the drives in place (like the outputs), so focus stays on the Sound theme row when a stick is plugged in; Down reaches the drive rows; after a copy the row disappears (the same folder and version are then installed) and `settleFocus` keeps focus in the pane; a drive row that has focus when the stick is ejected hands focus to a row of the pane (tests `test_a_drive_theme_is_copied_and_focus_survives_the_drive_list_changing`, `test_the_drive_row_that_has_focus_going_away_leaves_focus_in_the_pane`). No sound is ever the only signal: every cue sits next to a visible change (focus ring, toast, message, switch). Doubts: (1) a drive theme gets its own row instead of being an entry of the Sound theme choice row (see deviations); (2) the Ambient sound switch sits between the Ambient slider and Media, which moved the keyboard walk of `tst_audio` by one row; (3) in `sound-settings-en.png` and `-tr.png` (half size read) the long Turkish drive label fits on one line.

What was built:
- **Theme format and checker** (`shell/src/sound/SoundThemeCheck.{h,cpp}`): a pure function folder -> ok/problems/warnings/manifest, data only (sizes before reads, WAV parsed in memory, FLAC STREAMINFO and Ogg Vorbis/Opus head and last-page granule read for the length, nothing decoded, `..`/absolute/drive-letter/backslash paths and symlinks refused, unknown cue names are a warning). It also writes the fixture folders (`fixtureCases`, `writeFixtures`: 4 passing and 19 broken themes, one per limit and schema error). `ruya-shell --check-sound-theme <folder>...` and `--check-sound-theme-fixtures` run it without the UI; `scripts/lint-sound-themes.ps1` (in `dev.ps1 shell`/`test`) runs `make-sounds.py --verify`, the checker over `shell/sounds/dreamglass` and `samples/sound-theme-example`, and the fixtures.
- **`SoundThemes` singleton** (`SoundThemes.{h,cpp}`): bundled theme from `/usr/share/ruyaos/sounds/dreamglass` (Linux) else the Qt resource; `cues` map (active theme, else bundled per cue), ambient url/loop/gain, `themes` list, `refresh(mounts)` (worker thread, newest wins), `importTheme(path)` (only a listed drive theme; copies all regular files to the shell's data directory, re-checks the copy, at most 8 copies, 100 files, 12 MB), `selectedBroken` when the chosen theme fails the checker (log line, warning toast, bundled one plays). `DeviceSettings.soundTheme` (`dreamglass` or `user:<folder>`) and `ambientSound` (default on) are new, stored per device.
- **`Sfx.qml`**: one function and one counter for each of the 13 cues, `toggled(checked)`, `playedCount`, `duckCount`, silent while `IdleClock.covered` or the UI channel is 0, asks the bed to duck. Wired: toasts (`Notifications.promote`: sticky/warning/error -> `warning`, else `notification`), wrong PIN and refusals (`error`; the old `back` before warning toasts was removed so one event makes one sound), Guide overlay (`open`/`close` from `systemPanel.onOpenChanged`), section change (`page`), volume OSD (`volume`, not while muted), `ToggleRow` (`toggle-on/off` instead of `select`), start-up (first `frameSwapped`, once).
- **`AmbientLoop.qml`** (in `Shell`): two `MediaPlayer`s taking turns with a 1.5 s cross-fade at the loop end; 800 ms fade (not shortened by reduced motion) when an app is in front or the saver/dark screen/sleep starts, players paused when faded out; -8 dB duck under cues; switch and level from Settings.
- **Settings -> Audio**: Ambient sound switch, Sound theme choice, one row per valid drive theme. Turkish strings added.
- **Dreamglass** (`scripts/make-sounds.py`, numpy only, deterministic, CC0): 13 glassy cues (all below 0.7 of full scale, the longest 1.36 s, the largest 132 KB) and a 75.09 s mono 24 kHz pad as FLAC (619 KB) written by an encoder inside the script (numpy has no Vorbis encoder), every frequency and drift a whole number of cycles per loop. `--verify`: two runs identical, the limits, seam step 355 against a largest inner step of 487 (a revert that stops snapping the frequencies gives 8674 and fails), the FLAC decoded by the script's own decoder equals the samples, the repo files equal the generator's output. Also written: `samples/sound-theme-example/`.
- **Docs**: `docs/developers/sound-themes.md` (+ README row), spec `02` section 5.3 (and the channels line of section 5), `dev-setup.md`, `image-packages.md` (licence), `scripts/vm-sounds-check.sh` (lead run: files installed and root-owned, the shell's checker accepts Dreamglass and refuses a truncated cue, a `../` path and a symlink, no sound-theme complaint in the journal, licence file). `shell/CMakeLists.txt` installs `sounds/dreamglass` to `share/ruyaos/sounds` and the licence notice.

Checked here: the Qt ffmpeg backend (Windows, Qt 6.10) loads `ambient.flac` from the resource, reports 75093 ms and plays to the end (a throwaway probe, not kept). Not checked: Fedora's Qt (the image's ffmpeg-free must carry the FLAC decoder; Vorbis and Opus likewise), the output stream's PipeWire role, anything by ear.

Existing tests changed on purpose: `tst_audio` walks one row more (the Ambient sound switch); `tst_settings` asserts the toggle cues instead of `select` for a ToggleRow (stricter: on and off counted separately and `select` must not move); `tst_lockout` also counts the error cue per wrong PIN; `tst_main.cpp` sets `RUYA_SOUNDS_DRY=1` (the ambient players get no file in tests).

Revert tests (each new test fails when the change it covers is undone): `Sfx.fire` without the quiet/gain guard (`test_silent_while_the_screen_is_covered`, `test_gain_zero_is_silent`); `AmbientLoop.wanted` fixed true in Shell (`test_stops_when_an_app_is_in_front_and_returns`, `test_stops_when_the_saver_starts_and_returns`); duck fixed at 1 (`test_a_cue_ducks_the_bed_by_8_dB`); checker without the peak test and without the `..`/canonical-path tests (`test_cue_too_loud`, `test_path_escaping_the_folder`, `test_every_fixture_ends_as_expected`); no warning cue in `Notifications.promote`, the Guide `open` cue turned into `select` and the section `page` cue removed (`test_the_cues_are_wired_to_their_events`, one revert at a time); the start-up cue removed (`SoundStartup`); a wrong PIN on `back` again (`tst_lockout`); the pad's frequencies not snapped to whole cycles (`make-sounds.py --verify`). The volume-OSD cue was not reverted separately.

Deviations: (1) a drive theme is a row of its own ("Use “Name” from the USB drive") after the Sound theme choice row, not an option inside it: Left/Right on a choice row would copy a theme merely by browsing past it. (2) The ambient formats are Ogg Vorbis, Ogg Opus **and FLAC**, and Dreamglass ships as FLAC: the task wants the theme generated by a numpy script, which cannot write Vorbis or Opus; the FLAC encoder is in the script. (3) A cue the theme does not name falls back to the bundled one; a cue that is named but broken makes the whole theme refused (the task's "unknown cues fall back, a missing cue is silent" read this way); a theme without `ambient` has no ambient. (4) The ambient loop is two cross-faded players, so the manifest's `loop` start and end are honoured without a gapless decoder. (5) The timing constants (800 ms fade, 8 dB, 450 ms duck hold, 1.5 s cross-fade) live in `SoundThemes` and `AmbientLoop`, not in `Theme`: they are audio, not visual tokens (Inbox line). (6) Both the Qt resource and `/usr/share/ruyaos/sounds` carry the theme (1.1 MB twice in the image) so that the Windows build and a missing image folder still work.

Known failing on this machine and on main without my change: `Wallpaper::test_zz_screenshots` under `shots` ("captured once, not per frame", `sheet.bakeCount`): reproduced with main's own `tst_ruyashell.exe`; not caused by this task.
