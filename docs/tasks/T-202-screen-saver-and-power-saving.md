# T-202 — Screen saver and power saving: dim, blank, sleep, and idle controllers

Status: done · Phase: 2 · Depends: — · Area: shell, services, image · Size: M · Owner: builder

## Goal
A console left alone saves power and protects the screen, and wakes up instantly when touched. Owner request, 2026-11-06: "screen saver, power saving". After 10 minutes without input the screen shows a calm screen saver (and dims), later the display is switched off, later the console sleeps; none of that happens while something is going on (video, a download, an update being staged, an app that asks for the screen to stay on). Idle controllers are switched off by themselves.

## Scope
1. **One idle clock in the shell** (it is the compositor, so it sees every key, button and pointer event of every app): `idleSeconds`, reset by any input including controller input and the Guide button; exposed as a singleton for the saver, the display-off step and the update service report (replace the ad-hoc `ReportActivity` timing so there is one source).
2. **Inhibitors:** nothing idles while an app holds the Wayland `idle-inhibit` (`zwp_idle_inhibit_manager_v1`, which video players and games use; QtWaylandCompositor needs the protocol added: check support and say what was done), while a `Store`/`Update` job is running, while an installer is working, or while audio is playing to the shell's output (a music or video app). Each inhibitor shows in a debug row/log so a stuck inhibit is findable.
3. **Screen saver:** after the timeout (default 10 min) the shell shows a full-screen calm scene made from what it already has: the dimmed Home backdrop / installed apps' art slowly drifting and cross-fading, a small clock moving position every minute (burn-in safe on OLED), no focus ring, any input dismisses it and is **not** passed on to the page below (the first press only wakes). Effects off in the `performance` tier (a plain dimmed black with the moving clock); reduced motion = a static dimmed frame with the moving clock. Not shown while the picker/wizard asks for a PIN? (decide, record: it must never leave a PIN field visible and active under the saver).
4. **Display off:** after the next timeout (default 30 min) the display is switched off through KMS (DPMS off for the output) and back on at the first input; verify what the Dell's monitor does (some TVs lose the signal and re-sync slowly: record the wake time). If `eglfs_kms` cannot do DPMS, say so, find the least bad alternative (black frame + backlight) and record it.
5. **Sleep:** after the last timeout (default 60 min) `Power` suspends via logind, **only** when suspend is available and verified (T-166); wake by controller (Bluetooth wake enabled for bonded pads), keyboard, power button; after resume the shell is interactive in under 3 s (02 §8). If the OS cannot suspend, the option is not shown.
6. **Idle controllers:** a bonded Bluetooth pad with no input for N minutes (default 15) is disconnected by the service (`Disconnect`, it reconnects on the next button press: verified with the DualSense on the Dell, which already auto-reconnects) to save its battery; never while it is the only input device during an install/update screen? (decide, record).
7. **Settings -> Power saving** (a section in System or its own pane, decide per 02/04): Screen saver (Off / 5 / 10 / 15 / 30 min), Turn the screen off (Never / 15 / 30 / 60 min), Sleep (Never / 30 min / 1 h / 2 h / 4 h), Controllers turn off (Never / 5 / 10 / 15 / 30 min), and a **Power mode** row (Balanced / Power saver / Performance) only if a power-profile daemon is in the image (`power-profiles-daemon`: check whether it exists in the image, otherwise leave a one-line Inbox item). Defaults as above; stored in `DeviceSettings` (per device, not per profile).
8. **Docs:** a "Power saving" subsection in 02 and 01 §2.2 with the timeline table; the idle clock and inhibitors.

## Out of scope
- HDMI-CEC (turning the TV on/off with the console; a later task), Wake-on-LAN, hibernate, fan/thermal behaviour (T-200), per-profile timeouts, screen saver content from the Store.

## Outcome

VM (lead, 0.0.53, 2026-11-08): `vm-power-saving-check.sh` service, audio, timeline PASS; the journal shows `ruya-shell: idle-inhibit manager advertised` (the Wayland extension runs), `display off (dpms)` with `DPMS was used (eglfs_kms)` on the virtual GPU; the wake by key was not injected. **Built.** The shell's one idle clock, the saver, the dark screen, sleep, the inhibitors, the idle-controller rule and Settings -> Power saving. Specs: `01` §2.2 (timeline table, inhibitors), `02` §1.4a, `03` (service side), `dev-setup.md`.

- **One idle clock** (`shell/qml/IdleClock.qml`, singleton): `KeyRouter.activity` -> `IdleClock.noteInput()`; `idleSeconds` (real time since input), `quietSeconds` (held-awake time counts as activity; the stage countdown runs on it), `stage` (`active` -> `saver` -> `off` -> `sleep`; it only deepens, and only input or a clock jump after sleep leaves it). One timer aimed at the next deadline, stopped while held awake. Every time comes from `secs()` and `RUYA_IDLE_DIVISOR` (`IdleInhibit.timeDivisor`). The update report, `LiquidGate`, toasts and `UsagePresence` now hear input from `IdleClock.inputNoted`. **`UsagePresence`'s own clock is gone**: it asks `IdleClock.sample()` (held-awake time counts as present, so a game or film with a Wayland idle-inhibitor keeps counting past 10 minutes of silence). `Update.noteActivity`'s 60 s throttle stays: it limits bus calls, it is not a clock.
- **Consuming the wake input**: `KeyRouter.swallowInput` (bound to `IdleClock.covered`) eats the first key, button, pointer, touch or wheel event after reporting it, plus its release and the repeats of a held key; the page below never sees it and keeps its focus.
- **Inhibitors** (`IdleInhibit`, C++, counted reasons, logged `ruya-shell: idle inhibit +/-reason`, listed in the pane's "Keeping the console awake" row): `wayland:<n>` (compositor), `job` (`Store.jobs` non-empty: only jobs that reported progress; a job still queued behind another is not in that map), `update` (`Update.state` checking or downloading), `audio` (`Audio.playing`).
- **The audio inhibitor needed the service**: contract `Devices1.Audio.Playing` (property, XML first), `pipewire::parse_playing` (a PipeWire output node is `running`), `Snapshot.playing`, the change is announced with the other properties; shell `Audio.playing` with the mock (`mockSetPlaying`) and the D-Bus client (read with the existing GetAll).
- **Wayland `zwp_idle_inhibit_manager_v1`**: QtWaylandCompositor has no such extension. Added `shell/compositor/IdleInhibitManager.{h,cpp}` (a `QWaylandCompositorExtensionTemplate` over the vendored protocol file `idle-inhibit-unstable-v1.xml`, server glue generated by `qt6_generate_wayland_protocol_server_sources`), declared in `Compositor.qml`, which calls `IdleInhibit.acquire/release`. Each inhibitor counts while its object exists (the surface argument is ignored: an app that is not visible but holds one still holds the console; apps destroy the object when they stop). **Not compiled or run here** (the Windows kit has no QtWaylandCompositor): the first image build is its compile test. Image: `qt6-qtbase-private-devel` added to the shell build stage (for `ScreenPower`).
- **Display off** (`ScreenPower`, C++): `QPlatformScreen::setPowerState` of every screen (DPMS under `eglfs_kms`) from `<qpa/qplatformscreen.h>` (`Qt6::GuiPrivate`, which compiles on the Windows kit; a no-op there and offscreen, `supported` false). The black frame is always drawn, so without DPMS the picture is black and the monitor stays on (the log says `black frame only`). Backlight control was not attempted. **Unverified:** that `QEglFSKmsScreen::setPowerState` really switches the connector on the Dell or in the VM, and how long a TV takes to re-sync; the VM check prints which path was used.
- **Sleep**: `Power.suspend()` only when `Power.sleepAllowed` = logind `CanSuspend` and `/usr/share/ruyaos/suspend-verified` exists (or `RUYA_SUSPEND_VERIFIED=1`; the mock always allows it). Nothing creates the marker yet: **T-166 must create it when suspend is proven**, so on today's image the Sleep row is hidden and the step does not exist. After a suspend a clock jump counts as a wake (a power-button wake sends no key). Resume in under 3 s and Bluetooth wake are unverified (T-166, B-002).
- **Idle controllers**: contract `Devices1.Bluetooth.ReportIdle(u idle_seconds, u timeout_seconds, b hold)` (XML first); pure rule `services/ruya-devices/src/idle_pads.rs` (once per idle period; a pad counts from the moment it was seen connected, so a reconnect gets the whole time; a hold restarts the count), applied by `Bluetooth::report_idle`; shell backend, mock (`mockIdleReports` and friends) and D-Bus client. **Decisions:** the idle time is the console's (the service cannot see a pad's buttons, and `ruya-inputd` maps only A, B, Start, Guide, LB, RB, D-pad and left stick, so other buttons in a game never reach the shell): `hold` is true while an app is in front, so pads are never switched off during a game; likewise never while a job or update holds the console (an install or update screen keeps its only input device). With two pads, input on either keeps both on.
- **PIN rule (decision)**: the saver starts even over a PIN pad; every open `PinPad` clears its digits and cancels when `IdleClock.saverStarted` fires, so nothing is left typed or active behind it (a half-made PIN in a collect flow is dropped).
- **Saver look**: near-black ground (`Qt.darker(Theme.background, 20)`), installed apps' art full-bleed at 30 % drifting (zoom 1.1 to 1.22, pan) and cross-fading every 20 s, a `hh:mm` clock that takes a new place every minute inside the safe area. Performance tier: no art. Reduced motion: one still frame, the clock still moves. Off and sleep: black, no timers (`saverTick`, `saverSlides` stopped), `Backdrop` paused. Durations are `Theme.tintMs` multiples (so 0 under reduced motion).
- **Settings -> Power saving**: an own category before System (`PowerSavingPane`; System is now category 8 and About 9: the index constants in `tst_settings`, `tst_system_info`, `tst_thermal`, `tst_timezone`, `tst_update`, `tst_i18n`, `tst_hints`, `tst_pages`, `tst_glide_settings` and `tst_accessibility` moved by one), rows Screen saver, Turn the screen off, Sleep (only where allowed), Controllers turn off, "Keeping the console awake". Per-device `DeviceSettings.saverMinutes/screenOffMinutes/sleepMinutes/padIdleMinutes`. **Power mode row not added**: `power-profiles-daemon` is not in the image (Inbox line).

**Tests.** `shell/tests/tst_power_saving.qml` (29 tests, fake clock `IdleClock.now`): saver at exactly 600 s and not at 599; saver, off, sleep in order with their effects (`ScreenPower.on`, `Power.lastAction`); Off and Never skip a step; changing a setting applies at once; no sleep without suspend; input dismisses and is eaten (a probe item with focus sees 0 presses, the next press 1), also for the dark screen, a held key's repeats and the Guide button; a resume jump wakes; app, job, update and audio inhibitors prevent it and a release restarts the countdown, two holders need two releases, a late holder stops the next step; reduced motion and performance variants; the moving clock inside the safe area; the dark screen runs no timer; the PIN rule (real picker); idle-pad reports (timeout, hold with an app open, never, input ends the period at once); the update service still hears input; the pane writes the settings, focus after each step, Back; the Sleep row hidden. Rust: `idle_pads::tests` (6), `bluetooth::tests::an_idle_report_disconnects_only_connected_controllers_once`, `pipewire::tests::a_running_output_means_something_plays`, `audio::tests::playing_follows_pipewire_and_is_announced`. **Revert checks:** with `swallowInput: false` six tests failed; with the `audio` holder removed `test_audio_playing_prevents_idling` failed; with `told.insert` removed in `idle_pads.rs` two Rust tests failed. `tst_activity`'s presence test now drives `IdleClock.now` (the property it set no longer exists). UX notes: states reached: active, saver, dark screen (off), sleep. Back is not involved in waking: any key, button, Guide or pointer event wakes, is eaten, and the page below keeps its focus (asserted: the probe saw nothing; the page's focus is untouched); the PIN pad is the exception, it is closed and focus returns to the picker's list (asserted). **What cannot be verified here:** (1) input inside a game that does not reach the shell: the shell sees every event the window receives, including keys that go to a focused app (the `KeyRouter` filter runs first), but `ruya-inputd` turns only the navigation buttons into keys, so X, Y, the triggers and the right stick in a game are invisible: the game must hold an idle-inhibitor (SDL, mpv, Steam and most players do) or the presence and the saver treat the player as idle; the pad rule is safe regardless (hold while an app is in front); (2) real DPMS, TV re-sync, resume time, Bluetooth wake; (3) the DualSense disconnect and reconnect on the Dell; (4) the Wayland extension and `qt6_generate_wayland_protocol_server_sources` compiling on Fedora's Qt (the macro and the generated header name `qwayland-server-idle-inhibit-unstable-v1.h` are from memory of Qt's custom-extension example); (5) `Qt6::GuiPrivate` on Fedora (package added to the Containerfile).
